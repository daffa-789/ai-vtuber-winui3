## `release/` dihapus sebagian (22:52) — 1,3 GB bebas

`apps/stage-tamagotchi/release/` (2,1 GB, installer NSIS + `win-unpacked` era Go)
dihapus atas instruksi user. Hasil: **2,1 GB → 823 MB** (sisa satu berkas).

Rincian yang terhapus: `Silver-Wolf-Setup-0.1.0.exe` (376 MB), `.blockmap`,
`builder-debug.yml`, `builder-effective-config.yaml`, `latest.yml`, isi
`win-unpacked/` (17 dari 18 item, termasuk `locales/`, `electron.exe`, DLL Vulkan),
dan `resources/app.asar.unpacked/` (124 berkas).

**Yang gagal dihapus: `win-unpacked/resources/app.asar` (823 MB).** Dua sebab:
1. Berkas itu **terkunci proses lain** — terverifikasi lewat uji buka eksklusif
   (`[System.IO.File]::Open(...,'None')` gagal dengan "being used by another process").
   Tidak ada proses yang executable-nya di dalam `release/`, dan tidak ada proses
   bernama `wolf`; kandidat kuat `explorer.exe` (handle folder) atau `MsMpEng.exe`
   (Defender memindai berkas besar).
2. Ukuran 823 MB melebihi kapasitas Recycle Bin, sehingga `genie-trash` gagal, dan
   hook `safe-delete` bersifat **fail-closed** → menolak menghapus permanen.

**Jebakan lingkungan baru (penting):** hook `safe-delete` di lingkungan ini
mencegat `rm -rf` (Bash) **dan** `Remove-Item` (PowerShell), mengarahkannya ke
Recycle Bin, dan **menolak fallback delete permanen** kalau trash gagal. Akibatnya
berkas besar (> ~400-800 MB) tidak bisa dihapus dari dalam agen. Siasat yang berhasil:
hapus per-item (berkas kecil & sedang berhasil; folder besar gagal) alih-alih
menghapus folder besar sekaligus.

Saya **tidak** menembus hook itu dengan `[System.IO.File]::Delete()` — instruksi
sistem menyarankan menyesuaikan pendekatan atau menyerahkan ke user, bukan
mem-bypass guardrail.

Berkas scratch saya di `%TEMP%` (12 berkas hasil diagnosis) sudah dibersihkan.

## Backend Bun → Node (23:10)

User membatalkan Bun: *"gak jadi pake bun cukup node aja"*. Dikonfirmasi lewat
pertanyaan: **port backend ke Node, UI JSX tetap dipertahankan.**

- `apps/server-bun/` → **`apps/server-node/`**. `agent.ts` dan `inference.ts` **tidak
  perlu diubah sama sekali** — keduanya cuma pakai `fetch`/`TextDecoder`/`ReadableStream`
  yang sudah ada di Node 18+.
- Yang di-port hanya tepi I/O:
  - `llama.ts`: `Bun.spawn` → `node:child_process` spawn; `Bun.sleep` → `setTimeout`
    promise; `stop()` jadi non-blocking (SIGTERM + SIGKILL terjadwal 1,5 dtk).
  - `server.ts`: `Bun.serve` → `node:http` (`createServer`, `IncomingMessage`/
    `ServerResponse`, body dari event `data`/`end`, statis via `createReadStream`).
  - `main.ts`: `Bun.serve` → `createServer` + `listen`; port nyata dari `address().port`.
- `apps/server-node/tsconfig.json`: `types: ["bun"]` → `["node"]`.
- `package.json`: `bun` + `@oven/bun-windows-x64` dibuang dari dependensi,
  `@types/bun` dibuang, `esbuild ^0.25.12` ditambahkan, `engines.node` → `>=20.6`.
  Skrip: `server:dev` = `node --import tsx …`, `server:bundle` = `esbuild … --outfile=out/server/main.mjs`.
- Electron main: spawn Node. dev → Node sistem + `--import tsx` (cwd = akar repo);
  terkemas → `process.execPath` + `ELECTRON_RUN_AS_NODE=1` (Node bawaan Electron,
  **tanpa runtime tambahan di installer**). `extraResources` bun.exe dihapus.
- README, CI, dan komentar sumber diperbarui; `node_modules/@oven` (sisa staging npm)
  dihapus.
